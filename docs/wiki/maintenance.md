# 위키 유지보수 규칙

위키는 **현재 적용할 정책, 도메인의 의미·관계·예외, 재사용할 결정 이유**를 유지합니다. 파일 경로·코드 버전·작업 보고를 계속 복제하는 문서로 만들지 않습니다. [DEC-0017](decisions.md#dec-0017-정책도메인-중심-위키와-의미-변경-갱신)

## 언제 갱신하는가

| 변경 | 위키 처리 |
| --- | --- |
| 승인된 정책·권한·입력 조건·시간 규칙이 바뀜 | 해당 정책과 필요한 도메인 설명을 갱신합니다. 결정 이유가 바뀌면 결정 기록을 추가합니다. |
| 도메인 용어·관계·상태 전이·예외의 의미가 바뀜 | 해당 지식 문서를 갱신하고 영향을 받는 정책을 확인합니다. |
| 중요한 선택의 이유·대안·한계가 달라짐 | 결정 기록 또는 해당 지식을 갱신합니다. 미확정이면 후보로 남깁니다. |
| 정책 문서의 오류·불일치를 확인함 | 승인된 의도와 구현을 구분해 정정합니다. 새 정책을 추측해 만들지 않습니다. |
| 파일 이동·함수 이름·모듈 배치·내부 리팩터링만 바뀜 | 제품 의미가 같으면 위키를 갱신하지 않습니다. 개발 규칙 변경은 소유 스킬에서 관리합니다. |
| 테스트 실행·배포 버전·성능 수치·운영 데이터만 바뀜 | PR·배포 기록·로컬 변경 이력에 남깁니다. 위키에 실행 보고를 추가하지 않습니다. |

모든 코드 변경을 위키 갱신 사유로 삼지 않습니다. 최종 PR 준비에서는 위키 영향 여부를 확인하고, 의미가 바뀐 항목만 모아 반영합니다. 명시적으로 요청한 위키 수정은 요청 시점에 수행합니다.

## 문서에 담는 것

정책은 대상·허용 조건·거절 조건·예외를, 도메인 지식은 용어·관계·상태·경계를 적습니다. 결정 기록은 이유·대안·승인 근거·적용 범위와 날짜를 남깁니다. 상세 근거 링크는 독자가 판단할 때 필요한 최소한만 둡니다.

- 제품 정책의 현재 내용은 한 문서에서 소유하고 다른 문서에서는 연결합니다.
- 새 정책은 사용자 승인 또는 기존 승인 범위로 확정합니다. 구현을 관찰한 사실과 승인된 정책을 구분합니다.
- 구현 세부 목록, 긴 코드 설명, 테스트 개수·장비·배포 버전과 원본 작업 이력은 넣지 않습니다.
- 파일명이 바뀌면 문서를 고쳐야만 이해할 수 있는 표현보다 도메인 용어로 설명합니다.

## 작업과 PR에서의 적용

1. 작업에 관련된 정책·도메인 문서와 소유 스킬을 읽습니다.
2. 작업 중에는 이유·수정 범위·검증·배포·미확인 항목을 로컬 전용 `docs/change-history/CHANGELOG.md`에 남깁니다. 기존 기록을 지우지 않습니다. [DEC-0014](decisions.md#dec-0014-수정-작업-이력-기록-의무-도입)
3. 최종 PR 준비에서 위 표에 따라 의미가 바뀌었는지 확인합니다. 의미가 그대로면 위키를 수정하지 않고 PR에 그 이유를 적습니다.
4. 의미가 바뀌면 기존 문서의 해당 규칙을 고치고 필요한 결정·후보만 추가합니다. 개발 규칙 변경은 먼저 소유 스킬에 반영합니다.
5. 위키를 바꿨으면 `python3 scripts/check_wiki.py`를 실행합니다. 검사기를 바꿨으면 회귀 검사도 실행합니다. PR의 위키 영향에 변경한 정책·도메인 항목과 검사 결과를 적습니다.

정책 승인이나 소유 지침의 적용은 PR까지 미루지 않습니다. 승인된 범위에서 진행할 작업을 다시 승인받지 않습니다. 코드와 문서가 다르다는 이유만으로 관찰한 구현을 새 정책으로 확정하지 않습니다.

## 메타데이터와 근거

`authority: canonical`은 승인된 유지보수·기록 규칙, `authority: reference`는 정책과 도메인 지식을 정리한 참고 문서, `authority: none`은 미확정 후보·양식입니다. reference 문서에서도 명시적으로 승인된 정책과 기존 지식을 구분합니다.

`last_verified`는 **해당 지식의 내용과 승인 근거를 마지막으로 검토한 날짜**입니다. 매 코드 변경이나 단순 검사 실행마다 갱신하지 않습니다. 파일 이동·구현 리팩터링 후 전체 소스를 재검증했다고 표시하지 않습니다.

`source_ref`는 특정 구현을 근거로 남길 필요가 있을 때만 사용하는 선택 항목입니다. 모든 페이지에 커밋 해시를 요구하지 않고 최신 HEAD를 따라 갱신하지 않습니다. 정책 승인 근거는 결정 ID로, 작업별 구현·배포 검증은 PR과 변경 이력으로 확인합니다.

## 결정과 후보

기존 결정 ID와 승인 근거는 보존합니다. 정책을 대체할 때 새 결정에 대체한 ID를 연결하고 현행 정책을 갱신합니다. 정기적인 코드 변경에 새 결정을 만들지 않습니다.

미확정 후보에는 질문, 확인한 근거, 적용 범위와 한계, 다음 확인 방법을 적습니다. 반복 관찰이나 다른 프로젝트의 관행만으로 승인된 정책으로 승격하지 않습니다. 해소한 후보는 이유와 연결 문서를 남기고 불필요한 작업별 사용 횟수 목록은 늘리지 않습니다.

## 공유와 검사 한계

사용자 데이터·비밀키·비공개 URL·원본 대화·운영 증거는 공유 위키에 옮기지 않습니다. 로컬 전용 기록은 그 자료가 없는 checkout에서도 위키를 읽을 수 있도록 작성합니다.

위키 검사는 메타데이터·문서 링크·앵커·결정 ID·후보 상태의 정합성을 확인합니다. 정책의 승인 여부, 의미의 정확성, 현재 운영 배포 상태와 실제 동작은 별도의 근거 검토가 필요합니다. 최종 PR의 CI에서도 위키 검사를 실행하며, 위키 영향이 없는 코드 PR에 문서 수정이나 커밋 번호 갱신을 강제하지 않습니다.
