# 제품 정책

이 문서는 사용자가 할 수 있는 일, 경계 조건과 예외를 설명합니다. 명시적으로 승인된 변경은 결정 ID를 연결하고, 나머지 항목은 이전 문서에서 확인한 기존 도메인 규칙으로 유지합니다. 구현·배포 버전의 목록은 이 문서에 넣지 않습니다.

## 지도와 검색

- 하단의 주요 화면은 지도·랭킹·새소식·피드·마이입니다.
- 일본 지도는 한국 지도 안의 전환 버튼으로 열며, 일본 화면의 복귀 버튼이나 뒤로 가기로 한국 지도에 돌아옵니다. 각 지도의 카메라를 보존합니다.
- 일본 지도의 초기 위치는 도쿄역입니다. 키가 없는 환경에서는 준비 문구를 보여줍니다. 일본 매장 데이터 연결은 후속 범위입니다. 이 결정은 승인된 제품 정책을 기록하며, 그 자체로 각 클라이언트의 배포 완료를 뜻하지 않습니다. [DEC-0013](decisions.md#dec-0013-일본-google-지도-화면-추가)
- 지도 검색은 정규화한 입력 1~100자를 사용합니다. 한 글자는 매장명 정확 일치만 허용합니다. 비교할 때 검색어와 대상의 공백·대소문자 차이를 무시하되 글자는 연속해서 일치해야 합니다. 표시용 이름·주소는 유지합니다.
- 등록 매장은 매장명 정확 일치·접두 일치·연속 포함, 매장명과 지역·지점의 복합 일치, 행정구역 일치, 일반 주소 일치 순으로 찾습니다. 같은 우선순위에서는 기준 위치와 가까운 순서로 정렬하고 그 뒤 최대 50개를 선택합니다. 영업 안내문·지도 URL은 지도 검색의 매칭 대상에서 제외합니다. [DEC-0024](decisions.md#dec-0024-매장명-우선-검색과-지역장소-탐색)
- 지역명·도로명과 매장명은 순서를 바꾸거나 붙여 입력할 수 있습니다. 지점명을 상호 앞에 입력한 검색도 허용하되 한정어는 실제 지역·도로명 또는 상호에 포함된 지점명과 일치해야 합니다. 상호 전체에 이미 들어 있는 한정어를 덧붙인 검색도 허용합니다. 실제 상호에 연속 일치하면 지점명 순서 변경으로 다른 상호를 추정해 확장하지 않습니다.
- 장소 후보는 이름 전체, 대학의 통용 약칭 또는 명시한 목적지 유형이 맞아야 합니다. 주소 변환 결과에서도 입력에 없는 글자를 버려 다른 지역을 선택하지 않습니다. 매장명과 겹치는 모호한 읍·면·동·리 후보는 매장명 일치가 있으면 제외합니다.
- 매장 결과와 지역·장소 목적지는 함께 찾습니다. 매장·장소 조회가 정상 완료되고 매장 결과 없이 장소 후보만 하나이면 해당 위치로 바로 이동합니다. 여러 후보나 매장 결과가 함께 있으면 사용자가 선택하며, 이동한 화면 범위의 등록 매장을 보여줍니다. 행정구역 이름과 도로명의 글자 일치는 구분하며, 매장명 일치가 지역·주소 일치보다 우선합니다.
- 매장과 장소 결과를 함께 표시할 때는 매장 목록 위 지도에 작은 장소 바로가기를 둡니다. 매장 목록을 스크롤해도 바로가기를 유지하며, 장소 후보가 여러 개이면 바로가기에서 후보 목록을 열어 선택합니다. [DEC-0024](decisions.md#dec-0024-매장명-우선-검색과-지역장소-탐색)
- 매장 검색은 검색 당시 현재 위치로 정렬합니다. 장소 선택은 실제 GPS를 바꾸지 않으며 선택한 목적지 주변을 탐색합니다. 새 검색은 이전 매장·장소 요청을 함께 교체하고, 한쪽 조회가 실패해도 다른 쪽의 성공 결과는 유지합니다.
- 검색 호출 제한은 사용자에게 제한 이유와 재시도 안내로 전달합니다. 다른 요청 실패와 같은 의미로 처리하지 않습니다. 운영 한도의 구체적인 수치는 서버 설정에서 관리합니다.

## 매장 메뉴

- 메뉴 조회가 성공했지만 표시할 메뉴가 없으면 등록된 메뉴가 없다는 안내를 표시합니다. 실제 조회 실패와 구분합니다.
- 메뉴 갱신일이 없어도 메뉴를 조회할 수 있으며, 갱신일이 없다는 이유로 오류를 표시하지 않습니다.

## 리뷰 작성과 공개

내 리뷰와 다른 사람 리뷰 목록은 공통 가게 리뷰 카드를 사용합니다. 내 리뷰에서 카드 상단의 가게 요약을 선택하면 현재 목록 위에 가게 상세를 표시해 필터와 스크롤 상태를 유지합니다. 리뷰 본문을 눌러도 가게 상세는 열리지 않습니다. [DEC-0006](decisions.md#dec-0006-리뷰-목록의-가게-카드와-상세-표시-통합)

상세를 변경 없이 닫으면 내 리뷰 목록을 다시 조회하지 않습니다. 이 원칙은 상세 닫기에서 시작해 작성·수정·삭제 후 복귀에도 적용하는 변경 기록 방식으로 확장했습니다. [DEC-0007](decisions.md#dec-0007-내-리뷰-상세-닫기에서-목록-재조회-제외), [DEC-0008](decisions.md#dec-0008-리뷰-변경-기록으로-화면-동기화)

성공한 리뷰 작성·수정·삭제는 변경 기록을 통해 관련 화면에 반영합니다. 화면 복귀만으로 리뷰나 사진을 다시 불러오지 않습니다. 세션 전환, 접근 변경, 기록 공백처럼 상태를 복구할 이유가 있을 때 필요한 조회를 수행합니다. [DEC-0008](decisions.md#dec-0008-리뷰-변경-기록으로-화면-동기화)

리뷰 카드와 방문 기록 타임라인에는 최초 작성 시각부터 경과한 시간을 표시합니다. 1분 미만은 ‘방금 전’, 1분 이상 1시간 미만은 ‘n분 전’, 1시간 이상 24시간 미만은 ‘n시간 전’, 24시간 이상 7일 미만은 ‘n일 전’으로 표시합니다. 각 단위에 못 미치는 나머지는 버립니다. 7일(168시간)부터는 기기 시간대의 작성일을 `yyyy.MM.dd` 형식으로 표시합니다. [DEC-0044](decisions.md#dec-0044-리뷰-작성-시각의-상대-표기)

미래 시각은 ‘방금 전’으로 표시합니다. 날짜만 있는 기록은 기기 시간대에서 그날이 시작된 시각을 기준으로 계산합니다. 작성 시각을 해석할 수 없으면 시간 표기를 생략합니다.

- 리뷰를 작성하거나 수정해 저장하려면 사진 첨부 여부와 관계없이 앞뒤 공백을 제외한 본문이 Unicode code point 기준 5~500자여야 합니다. 본문은 비속어를 검사하며 사진은 최대 5장입니다. 기존에 등록한 사진 전용 리뷰는 열람할 수 있습니다. [DEC-0041](decisions.md#dec-0041-리뷰-본문-최소-5자-필수), [DEC-0045](decisions.md#dec-0045-리뷰-본문과-사진-한도-확대)
- 비공개 프로필에서 공개 리뷰를 제출하면 팔로워에게 리뷰를 공개하는 설정과 무관하게 프로필을 비공개로 유지할지 공개로 바꿀지 확인합니다.
- 저장 실패 시 작성 중인 초안을 유지합니다.
- 공개 여부와 게시·검수 상태를 구분합니다. 다른 사용자의 목록에 작성자에게만 허용되는 비공개 결과를 섞지 않습니다.
- 로그인한 사용자는 공개 프로필에서 게시 중인 자신의 공개 리뷰에도 좋아요를 누르고 취소할 수 있습니다.
- 탈퇴한 회원의 리뷰와 첨부 사진은 보존합니다. 일반에 공개되던 리뷰에는 작성자를 ‘탈퇴한 사용자’로 표시하고 프로필 링크를 제공하지 않습니다. 비공개 리뷰와 비공개·정지 프로필의 리뷰는 일반에 공개하지 않으며, 기존 검수 상태를 유지합니다. [DEC-0043](decisions.md#dec-0043-탈퇴-회원의-리뷰-보존)

### 리뷰 공유·알림과 댓글 신고

- 일반 공개 상태로 게시 중인 리뷰는 링크로 공유할 수 있습니다. 링크를 열 때 현재 공개·접근 권한을 다시 확인합니다.
- 계정의 리뷰 알림을 켜면 다른 사람이 내 리뷰에 남긴 댓글과 내 댓글에 달린 답글을 받을 수 있습니다. 전체 리뷰 알림은 처음에 꺼져 있습니다. 작성자는 자신의 리뷰에서 그 리뷰에 대한 본인의 수신을 별도로 끌 수 있습니다.
- 댓글과 답글은 기존 커뮤니티 이용규칙과 신고 사유를 적용합니다. 로그인한 사용자는 볼 수 있는 다른 사람의 댓글·답글을 신고할 수 있습니다. 동일 사용자·대상의 대기 신고는 한 건을 유지하며, 운영자가 접수 내용을 검토합니다. [커뮤니티 이용규칙](../../community-guidelines.html)

## 프로필과 다른 사용자 접근

- 공개·비공개·차단·이용 불가 상태를 구분해 처리합니다.
- 프로필 방문 매장 순위는 매장별 리뷰 수를 방문 횟수로 표시합니다. 본인 프로필에서는 본인이 작성한 리뷰를 집계하고, 다른 사람 프로필에서는 기존 리뷰 열람 권한이 허용될 때 공개·게시 중인 리뷰만 집계합니다. 서비스에서 공개 중인 매장만 포함합니다.
- 방문 순위 카드는 순위가 분명한 상위 3개 매장이 있을 때 표시합니다. 집계된 매장이 정확히 3곳이고 세 매장이 모두 단독 순위이면 시상대만 표시합니다. 3위와 4위를 구분할 수 있을 때만 최대 10개 매장의 목록을 펼칠 수 있습니다. 4위 이하에서 방문 횟수가 같은 매장은 순위를 숫자 대신 ‘-’로 표시합니다. 동률 판정에는 목록 상한 밖의 다음 매장과의 동률도 포함하며, 동률이 상위 3위나 3위와 4위 사이에 있으면 시상대를 표시하지 않습니다. 집계 매장이 0~2곳이면 카드를 숨깁니다.
- 비공개 계정에서도 닉네임과 현재 프로필 사진은 공개합니다. 리뷰·저장 목록의 공개 범위와 차단·정지·탈퇴 조건은 별도로 유지합니다. [DEC-0015](decisions.md#dec-0015-비공개-계정의-닉네임프로필-사진-공개-확정)
- 인스타그램 아이디 입력 기능은 제공하지 않습니다.
- 자기소개 등 사용자 입력은 앱과 서버에서 검증합니다. 잘못된 자기소개를 서버 오류로 취급하지 않고 입력 오류로 반환합니다.

## 제보 사진

새소식·이벤트 URL이나 사진을 제출하는 사용자 제보는 제공하지 않습니다. 아래 접근·삭제 조건은 기존 제보 자료에 적용하며, 기존 자료는 보존합니다. [DEC-0023](decisions.md#dec-0023-새소식이벤트-사용자-제보-제거)

사진에는 개인정보나 검토 중인 자료가 포함될 수 있으므로 공개하지 않습니다. 로그인한 제보자와 별도 등록한 관리자만 열람할 수 있습니다. [DEC-0016](decisions.md#dec-0016-제보-사진의-제보자관리자-열람-제한)

| 행동 | 조건 |
| --- | --- |
| 사진 열람·목록 조회·새 링크 발급 | 제보자 본인 또는 등록 관리자만 허용합니다. |
| 제보자가 사진 삭제 | 아직 제보에 연결되지 않은 본인 사진만 허용합니다. |
| 제출된 사진 삭제 | 관리자만 정리합니다. |
| 기존 소유자 불명 사진 열람 | 제보자를 추측해 지정하지 않고 관리자만 허용합니다. |
| 기존 사진 덮어쓰기 | 허용하지 않습니다. |

발급된 서명 링크는 만료 전 소지자가 사용할 수 있으며 이미 내려받은 파일까지 회수하는 정책은 아닙니다.

## 저장 목록과 랭킹

비로그인 사용자도 매장을 기기에 저장하고 해제할 수 있습니다. 지도, 매장 상세, 랭킹, 새소식과 마이의 저장 목록은 같은 저장 상태를 사용합니다. 기기에만 저장한 매장은 서버의 매장별 저장 수와 랭킹 집계에 포함되지 않습니다.

로그인하면 기기 저장을 계정의 기존 저장에 중복 없이 추가합니다. [계정 전환과 이전 규칙](app-flows.md#앱-진입과-계정-전환)을 따릅니다. 가져오기와 피드의 저장한 매장 필터는 계정이 필요합니다. 가져오기에서는 이미 저장한 매장을 후보에서 제외하고 사용자가 선택한 나머지를 저장합니다.

개인 매장 숨기기 기능은 종료합니다. 이전에 숨긴 매장도 서비스에서 공개 중이면 지도·검색·가져오기에 다시 표시합니다. 숨길 때 해제된 저장과 매장 알림은 사용자가 다시 설정할 수 있습니다. [DEC-0042](decisions.md#dec-0042-개인-매장-숨기기-종료)

랭킹은 페이지 사이의 중복을 제거하고 같은 순위에서 다음 순위를 건너뛰지 않는 dense rank를 유지합니다. 북마크 표시 변화로 이미 받은 랭킹 순서를 재정렬하지 않습니다.

## 이벤트와 영업 변경

- 새소식·이벤트 목록은 신메뉴·리뉴얼을 제외한 등록 이벤트를 유형 선택 필터 없이 함께 보여줍니다. 기존 신메뉴·리뉴얼 데이터는 보존합니다. 신메뉴·리뉴얼·이벤트 사용자 제보는 받지 않습니다. [DEC-0023](decisions.md#dec-0023-새소식이벤트-사용자-제보-제거)
- 이벤트 상세의 결과 없음과 조회 실패를 구분합니다. 조회 실패에는 재시도할 수 있는 흐름을 제공합니다.
- 일반 이벤트는 선택한 시작일과 종료일을 유지합니다. 신메뉴는 7일 기간, 리뉴얼은 종료일 없음이라는 기존 규칙을 유지합니다.
- ‘영업 변동’은 전체 기능명이며 등록할 공지 유형은 **임시 휴무·조기 마감·운영 변동** 세 가지입니다. 임시 휴무는 해당 날짜에 영업하지 않음, 조기 마감은 정상 영업 중 수량 소진 등의 이유로 실제로 일찍 마감함, 운영 변동은 사전에 정해진 사유에 따른 단축 영업을 뜻합니다. 일반 영업시간 변경과 오픈 지연은 공지 유형으로 제공하지 않습니다. [DEC-0019](decisions.md#dec-0019-영업-변동-세-유형과-목록-필터)
- 공지는 선택한 시작일부터 종료일까지 적용하며 월을 넘길 수 있습니다. 날짜 역전·존재하지 않는 날짜와 같은 공지의 중복 등록을 거절합니다. 월간 달력에서는 명시된 휴무 날짜만 개별 임시 휴무로 등록하고, 언급하지 않은 날짜는 휴무로 처리하지 않습니다.
- 매장 상세에서는 임시 휴무 당일에 연한 붉은 배경의 상단 카드로 **오늘 휴무**를 한 번만 표시합니다. 그 아래에 하루 휴무는 **10/24(토)**, 연속 휴무는 **10/24(토) ~ 10/30(금)**처럼 요일을 포함한 전체 기간을 항상 보여줍니다. 제목의 종료일과 별도의 임시 휴무일 안내는 중복 표시하지 않습니다. **정규 영업시간**은 별도 영역으로 기본 접힌 상태이며 누르면 요일별 시간을 보여줍니다. 정규 시간 정보가 없으면 빈 펼치기 영역을 만들지 않습니다. 검색 결과처럼 한 줄로 표시하는 곳은 하루 휴무에 **오늘 휴무**, 연속 휴무에 **오늘 휴무 · 10/30까지** 형식을 유지합니다. 떨어진 휴무일은 하나의 연속 기간으로 표시하지 않으며, 휴무 중에는 다음 영업 시각이나 종료일 다음 날의 영업 재개를 추정해 안내하지 않습니다. [DEC-0029](decisions.md#dec-0029-매장-상세의-휴무-카드와-정규-영업시간-분리)
- 임시 휴무는 해당 날짜의 정규 영업시간보다 우선합니다. 조기 마감과 운영 변동은 정확한 마감 시각을 확인한 뒤 등록하며, 그 시각부터 매장 상세·검색 결과 등에서 **‘영업 종료’**로 표시합니다. 마감 전에는 정규 영업 및 브레이크타임을 따르되 표시할 종료 시각은 확인된 마감 시각을 반영합니다. 중복 공지는 임시 휴무를 우선하고, 시간 기반 공지 중 가장 이른 종료를 적용합니다. 종료 시각이 같으면 실제 조기 마감을 우선합니다.
- 정확한 시각이 없는 ‘점심만 영업’ 등의 문구만으로 마감 시각을 자동 추정하지 않습니다. 사전에 공지된 점심만 영업·저녁 휴무는 운영 변동으로 구분하고 특정 메뉴 품절만으로 매장 조기 마감으로 판단하지 않습니다. 과거 조기 마감을 원문 확인 없이 재분류하지 않습니다. 확인되지 않은 기존 조기 마감 공지는 공개하지 않고 원본을 보존합니다.
- 매장 상세에서는 별도의 `조기 마감 >` 링크를 표시하지 않습니다. 상세 영업 변동 공지 카드에도 마감 시각을 별도 행으로 표시하지 않으며, 시각은 영업 상태 판단에 사용합니다.

새소식 영업 변동은 ‘오늘의 운영 변동’과 ‘예정된 운영 변동’을 한 화면의 매장별 목록으로 함께 보여줍니다. 오늘 적용되는 진행 중 공지는 오늘 섹션에만 표시하고, 시작일이 오늘보다 늦은 공지만 예정 목록과 예정 상세에 표시합니다. 같은 매장에 서로 다른 오늘 공지와 미래 공지가 있으면 각 섹션에 표시하며, 예정 섹션 안에서는 날짜가 여럿이어도 매장을 한 번 표시합니다. 오늘 매장을 선택하면 오늘 적용되는 공지를, 예정 매장을 선택하면 그 매장의 아직 시작하지 않은 유효한 공지들을 함께 확인합니다. 공지의 적용 날짜·기간과 원문 본문은 보존합니다. [DEC-0025](decisions.md#dec-0025-새소식의-매장별-목록과-검색저장-필터-복원), [DEC-0031](decisions.md#dec-0031-진행-중인-영업-공지와-시작-전-공지의-목록-분리)

이벤트와 영업 변동 목록은 각 탭의 저장 필터로 저장한 매장의 소식만 모아 볼 수 있습니다. 저장 필터는 비로그인 상태에서도 기기의 저장 목록을 사용합니다. 개인화 로딩·실패는 저장한 매장 없음과 구분하며 로그아웃·계정 변경 시 해당 사용자의 목록을 다시 적용합니다.

## 매장 알림 설정

- 사용자는 매장 상세의 알림 설정에서 서버가 제공하는 유형을 매장별로 선택하고 저장할 수 있습니다. 유형 카탈로그가 선택 가능한 항목의 기준입니다.
- 기존 이벤트 알림은 다른 유형을 추가하거나 수정할 때 이벤트 선택을 바꾸지 않은 경우 유지합니다. 전체 해제를 선택하면 해당 매장의 알림 선택을 모두 해제합니다.
- 알림 유형을 선택해 저장한 것과 운영체제 권한, 기기 푸시 등록, 실제 알림 수신은 별개입니다. 각 상태를 혼동하거나 수신을 보장한다고 안내하지 않습니다.
- 승인된 임시휴무·조기 마감·단축 영업 공지를 새로 등록하면 해당 매장과 유형을 구독하고 지원 기기를 등록한 사용자에게 자동 알림을 발행합니다. 기존 공지를 일괄 재발송하지 않으며, 동일 등록에 대한 처리 재시도로 중복 발송하지 않습니다. 발송 전에 공지가 수정되거나 삭제되면 이전 내용의 대기 알림을 취소합니다.
