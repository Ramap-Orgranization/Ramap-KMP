# 이미지 링크 공유 캐시의 채택 근거 보완

## 처리 결과

사용자 승인으로 기본 배치를 채택하고 앱에 적용했다. [DEC-0003](../decisions.md#dec-0003-이미지-링크-기본-배치-발급-채택), [적용 후 보고서](../../performance/image-url-cache/APPLIED-BATCH.md)를 따른다. 아래는 검토 당시 기록이며, Redis가 현행 앱 경로라는 뜻은 아니다.

## 내용과 근거

- 확인할 판단: 서버 공유 캐시가 Supabase 기본 일괄 발급에 비해 운영 비용과 복잡성을 정당화하는가.
- 구현: [이미지 캐시 탐색](../image-url-cache.md). 현재 Cache-Aside, 절대 TTL, 파일 버전 키,
  요청자별 권한 재확인, 임시 잠금, Redis 장애 시 직접 발급을 사용한다.
- 사용자 요구: 서버 측 재사용 및 개선의 수치화에 이어 선택 이유와 대안 비교 근거를 요구했다.
  특정 캐시 패턴이나 TTL을 팀의 확정 정책으로 승인한 요청은 아니다.
- 후속 실측: [동일 조건 비교](../../performance/image-url-cache/CONTROLLED-COMPARISON.md)에서
  기본 배치 p50 207.54ms, Edge 배치 317.62ms, Redis 적중 685.35ms(각 30회).
  동일 개별 처리 코드에서 Redis만 바꾼 10쌍의 평균 차이 구간은 0을 포함했다.
  현재 입력에서는 기본 배치를 우선 권고하며, 아직 운영 구조 전환이 확정되거나 반영된 것은 아니다.
- 미확인 범위: 실제 경로 재사용률, 실기기/다른 화면/동시 부하에서의 일반화,
  Disk IO 변화, Upstash 실제 퇴출 설정, 장애 중 중복 발급/원본 부하, 30분에서 5분으로 바뀐 내 프로필 재사용의 영향.
- 다음 확인: 기본 배치 적용 시 Kotlin SDK의 부분 오류·세션 변경·취소 동작 및 실기기 성능을 검증한다.
  Redis 재검토에는 실제 재사용률과 서명/권한 조회의 DB 비용 근거가 필요하다. 권고를 정책으로 자동 승격하지 않는다.
