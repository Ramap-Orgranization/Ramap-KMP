# 사용자 흐름

사용자에게 보이는 단계와 실패·복귀의 의미를 설명합니다. 내부 클래스의 호출 순서는 구현에서 확인합니다.

## 앱 진입과 계정 전환

앱 시작 시 최소 지원 버전을 확인합니다. 최소 빌드에 미달하고 지원하는 스토어 주소가 있으면 업데이트로 안내합니다. 확인 요청 실패나 시간 초과만으로 앱 진입을 막지 않습니다. 앱 공지는 콘텐츠 위에 표시하며 콘텐츠 진입을 기다리게 하지 않습니다.

처음에는 개인화 정보의 로딩·오류를 처리합니다. 이미 열린 화면은 이후 새로고침만으로 다시 진입시키지 않습니다. 로그인·로그아웃·계정 전환 시 개인화와 프로필 상태를 다시 확인하고, 이전 계정의 진행 중 작업이나 늦은 결과가 새 계정에 섞이지 않도록 처리합니다.

## 지도 검색과 상세

1. 사용자가 검색어를 입력하면 입력 조건을 확인합니다.
2. 새 검색이 시작되면 이전 검색을 교체합니다.
3. 정상 조회 결과가 장소 하나뿐이면 해당 위치로 바로 이동합니다. 장소 후보가 없고 열람 가능한 매장이 하나이면 상세를 엽니다. 여러 후보나 매장·장소가 함께 있으면 목록에서 선택합니다.
4. 호출 제한은 재시도 안내로, 일반 실패는 실패 안내로 구분합니다.

장소 후보를 선택하면 해당 좌표로 지도를 이동하고 화면 범위의 등록 매장을 조회합니다. 검색 목적지는 사용자 GPS와 구분하며 이후 수동 지도 이동에서도 주변 매장을 계속 탐색합니다. 매장 결과가 있다는 이유로 장소 후보 검색을 생략하지 않고, 한쪽 요청의 실패만으로 다른 성공 결과를 지우지 않습니다. [검색 정책](product-policy.md#지도와-검색)

매장과 장소 결과가 함께 있으면 매장 목록 위의 작은 장소 바로가기에서 목적지를 선택합니다. 장소 후보가 여러 개이면 바로가기를 눌러 후보 목록을 엽니다. 바로가기는 매장 목록의 스크롤과 분리해 유지합니다.

가게 상세의 기본 정보·메뉴·리뷰는 각각 조회합니다. 상세를 처음 열면 세 조회가 모두 성공 또는 실패로 끝날 때까지 전체 스켈레톤을 보여줍니다. 기본 정보가 상세의 진입 기준이므로 최초 기본 정보 조회 실패는 상세 전체 오류로 표시하고, 기본 정보가 성공했을 때 메뉴·리뷰 실패는 해당 영역에서 표시합니다. 실패한 부분만 재시도하며, 최초 조회 이후의 재시도와 리뷰 추가 로딩은 해당 영역에서 처리합니다. 이미 표시한 기본 정보의 갱신만 실패하면 기존 내용을 유지합니다. 상세를 닫거나 선택한 가게를 바꾸면 진행 요청, 최초 완료 여부, 조회 상태, 로그인 후 실행을 기다리던 상세 액션을 함께 정리합니다. 다시 열면 해당 가게를 새로 조회합니다. 상세를 닫는 일만으로 원래 리뷰 목록을 다시 조회하지는 않습니다.

## 한국·일본 지도 전환

한국 지도 안의 전환 버튼에서 일본 지도를 엽니다. 일본 화면의 복귀 버튼 또는 뒤로 가기로 기존 한국 지도에 돌아오며 각 지도의 카메라를 보존합니다. 반복 전환으로 같은 화면을 중복해서 쌓지 않습니다. 매장 링크는 한국 매장 지도에서 처리합니다.

일본 지도는 도쿄역에서 시작합니다. 키가 없으면 준비 문구를 표시하고, 매장 데이터·마커·검색은 후속 범위입니다. 키와 SDK 설정 방법은 구현·개발 자료에서 관리합니다. [결정 이유](decisions.md#dec-0013-일본-google-지도-화면-추가)

## 매장 링크로 진입

매장 링크를 받으면 해당 매장을 여는 흐름에 전달합니다. 이전 링크를 처리하는 도중 새 링크가 들어와도 새 링크를 유실하지 않습니다. Android와 iOS가 내부적으로 같은 진입 경로를 사용한다고 가정하지 않습니다.

## 리뷰 작성·저장·복귀

입력과 공개 조건을 확인한 뒤 저장합니다. 저장 실패는 초안 유실로 이어지지 않도록 처리합니다. 수정·삭제 결과는 여러 화면에서 같은 리뷰를 다룬다는 점을 고려합니다. 목록의 현재 페이지와 작성자 전체 집계는 서로 다른 정보입니다.

다른 사용자의 리뷰로 이동하면 프로필 접근 상태를 다시 확인합니다. 비공개·차단·이용 불가를 단순한 빈 목록으로 합치지 않습니다.

## 이벤트와 알림

등록된 이벤트는 유형 필터 없이 진행 중·예정 목록에서 함께 탐색합니다. 신메뉴·리뉴얼·이벤트를 새로 제보하는 흐름은 제공하지 않습니다. 이벤트 상세에서 결과가 없으면 이용 불가로, 조회가 실패하면 재시도 가능한 실패로 처리합니다. 알림 선택에는 [설정 시간 창](product-policy.md#이벤트-알림)이 적용됩니다. 선택을 저장한 것과 실제 푸시 수신은 서로 다른 단계입니다.
