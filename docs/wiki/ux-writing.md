# UX Writing

[토스 UX Writing 가이드](https://github.com/toss/apps-in-toss-harness/blob/main/packages%2Fagent-plugin%2Fshared%2Fskills%2Fux-writing%2FSKILL.md)의 원칙을 라멥 문구 검토용으로 요약했습니다. 실제 기능·조건은 [제품 정책](product-policy.md)과 [사용자 흐름](app-flows.md)을 확인합니다.

## 앱 이름

사용자가 지정한 앱 이름은 **라멥**입니다(2026-10-22). 화면과 공유 문구에서 같은 표기를 사용합니다.

## 적용 범위

문구 변경은 `AGENTS.md`에 따라 사용자가 명시적으로 요청한 범위에서 진행합니다. 이 문서의 추가가 기존 화면 문구의 변경 승인을 뜻하지는 않습니다.

## 문구 원칙

- 사용자가 하려는 일과 기다리는 대상을 설명합니다.
- 손해·불안으로 재촉하지 않고 얻는 가치를 전달합니다.
- 감정을 추측하지 않고 사실을 안내합니다.
- 복잡한 조건·금액·기간은 항목으로 나눕니다.
- 제목·설명·본문에서 같은 주장을 반복하지 않습니다.
- 실패에는 확인된 이유와 다음 행동을 안내합니다.
- 버튼에는 선택 후 일어날 행동을 적습니다.
- 존댓말·숫자·단위는 일관되게 씁니다. 해요체를 일괄 강제하지 않습니다.
- 화면의 기본 언어를 일관되게 사용합니다.
- 동의·거절을 재촉하거나 선택을 압박하지 않습니다.

## 상황별 예시

아래는 설명용 가상 문구입니다. 실제 동작과 제공하는 선택지를 확인해 제안합니다.

| 상황 | 표현 예시·작성 방향 |
| --- | --- |
| 로딩 | 매장을 불러오고 있어요. |
| 검색 결과 없음 | 검색된 매장이 없어요. 검색어를 바꿔보세요. |
| 연결 실패 확인 | 인터넷 연결을 확인한 뒤 다시 시도해주세요. |
| 위치 권한 요청 | 주변 매장을 찾으려면 위치 접근이 필요해요. |
| 등록 버튼 | 리뷰 등록하기 |
| 선택 동의 | 제공 목적과 거절해도 이용할 수 있는 범위를 안내합니다. |
| 기간·조건 | 기간·금액·대상을 각각 나눠 표시합니다. |

오류 원인은 확인된 경우에만 단정합니다. 권한·동의의 대안 경로는 실제 지원 여부를 확인하고, 법률·약관 문구는 공식 근거를 확인합니다.

## 검토 절차

1. 정상·로딩·빈 상태·실패·권한 문구를 모읍니다.
2. `화면 / 위치 / 원문 / 수정안 / 이유`로 제안합니다.
3. 사용자 요청·승인 범위의 항목을 적용합니다.
4. 의미·어투와 줄바꿈·잘림·겹침을 확인합니다.
