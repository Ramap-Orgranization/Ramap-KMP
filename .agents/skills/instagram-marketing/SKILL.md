# Instagram Marketing

Ramap 공식 인스타그램 게시물 초안을 만든다. 기존 계정의 정보형 카드뉴스 스타일을 유지하면서 사용자의 문제를 먼저 제시한다.

## Agent routing

Primary agent는 `AGENTS.md`, `.codex/agents/sol/terra-instagram-marketer.toml`, `.codex/agents/sol/instagram-marketer.md`와 이 스킬을 읽고 named role `terra_instagram_marketer`에 초안 기획을 위임한다. 모델과 추론 수준은 TOML을 기준으로 선택하며, named role을 사용할 수 없으면 같은 설정으로 별도 에이전트를 생성한다.

홍보 대상, 확인된 사실, 타깃, CTA, 제공 이미지와 확정 문구를 전달한다. 담당 에이전트는 같은 작업을 다시 위임하지 않고 요청된 초안만 작성한다. 결과를 기다린 뒤 사실 확인 항목과 게시 승인 여부를 사용자에게 함께 전달한다. HTML 카드뉴스 시안과 PNG·ZIP 제작 요청은 `instagram-carousel-prototype` 스킬을 적용한다.

## Invocation

- `/instagram-marketing`
- 기능, 매장, 이벤트 또는 게시물 소재를 주고 인스타그램 게시물을 만들어 달라는 요청

## Required input

가능하면 다음을 받는다.

- 홍보 대상과 핵심 사실
- 예상 독자 또는 상황
- 사용자가 하길 원하는 행동
- 사용할 이미지나 앱 화면

누락된 값은 한 번에 필요한 것만 질문한다. 가격, 날짜, 위치, 운영 조건처럼 사실성이 중요한 값은 추측하지 않는다.

## Draft workflow

1. 게시물 목표와 타깃을 정의한다.
2. 사용자의 실제 문제를 한 문장으로 정리한다.
3. `문제 제시 → 공감 확대 → 관점 전환 → Ramap 해결책 → 사용자 변화 → CTA` 순서로 기획한다.
4. 첫 장 제목 후보 3개를 만든다.
5. 카드뉴스 장별 문구와 시각 구성을 작성한다.
6. 캡션과 관련성 높은 해시태그를 작성한다.
7. 사실 확인 목록과 불확실성을 표시한다.
8. 사용자가 수정하거나 승인할 수 있는 초안으로 끝낸다.

결과에는 목표·타깃, 추천 콘셉트, 첫 장 제목 후보, 카드별 문구·시각 요소, 캡션, 하나의 CTA, 해시태그, 게시 전 사실 확인 목록과 기존 계정 스타일에서 벗어나는 지점을 포함한다.

## Visual asset workflow

이미지 제작 또는 수정 요청이 있으면 다음 규칙을 적용한다.

- 인스타그램 피드는 3:4(1080×1440), 스토리는 9:16(1080×1920) 기준으로 제작한다.
- 스토리는 상단·하단의 인스타그램 UI 안전 영역을 비워둔다.
- 제공된 앱 스크린샷은 실제 화면을 임의로 다시 그리지 않고, 원본 세로 비율과 내부 텍스트·아이콘을 보존한다.
- 화면이 카드보다 길면 찌그러뜨리지 말고 축소한 뒤 좌우 또는 상하 여백을 둔다.
- 수정 요청은 변경 영역만 편집한다. 텍스트 제거 요청에서는 카드 바깥 문구와 스크린샷 내부 문구를 구분한다.
- 텍스트 크기 수정은 문구, 색상, 정렬과 브랜드 스타일을 유지한 채 크기와 여백만 조정한다.
- 이미지 결과에는 목적(피드/스토리), 비율, 변경 내용과 생성 파일 경로를 함께 보고한다.
- 이 스킬의 피드 기본값은 3:4이고 `instagram-carousel-prototype`의 HTML 시안 기본값은 4:5이다. 사용자가 지정한 규격을 우선하고, 기존 시안의 비율을 바꾸는 것은 별도의 변경으로 다룬다.

## 콘텐츠 사이즈 가이드

다음 기준은 [YJ Factory의 2026 인스타그램 콘텐츠 사이즈 가이드](https://www.instagram.com/p/DUCbRlokwrA)를 따른다. 플랫폼 노출 규격은 바뀔 수 있으므로, 업로드 직전 최신 규격을 다시 확인한다.

- 피드 이미지·캐러셀: 1080×1440px, 3:4
- 스토리: 1080×1920px. 핵심 콘텐츠는 중앙 1080×1420px 안전영역에 배치하고 상·하단 250px은 비운다.
- 릴스 썸네일: 원본 1080×1920px. PC 노출을 고려해 상·하단 각 120px을 제외한 중앙 1080×1680px 안에 핵심 요소를 둔다. 모바일은 전체 1080×1920px이 노출된다.
- 탐색 탭 썸네일: 최신 노출은 1080×1440px, 기존 노출은 1080×1080px이다. 두 비율 모두에서 제목·얼굴·CTA가 잘리지 않도록 주요 요소는 중앙에 둔다.

## Text correction

- 사용자가 확정한 문구를 제공했거나 레이아웃 조정만 요청하면, 문구·문장부호·의도한 문단 구분을 원문 그대로 유지한다. 표현을 다듬거나 줄바꿈을 추가·제거하지 않는다.
- 확정 문구가 아닌 초안의 명백한 오탈자는 자연스러운 표현으로 바로잡되, 결과 보고에서 수정 사실을 알린다.
- 의미가 달라질 수 있는 표현은 임의로 고치지 않고 사용자에게 확인한다.
- 사용자가 “나머지 텍스트 제거”라고 하면 새 문구를 임의로 추가하지 않는다.

## Approval boundary

게시, 메시지 전송, 외부 업로드, 광고 집행은 별도 명시적 승인이 있을 때만 수행한다. 승인 전에는 초안 작성과 검토만 한다.

## Quality checklist

- 첫 카드만 보아도 사용자의 문제가 이해되는가?
- 공감 문구가 실제 상황을 구체적으로 보여주는가?
- Ramap의 해결책이 기능 나열이 아니라 사용자 변화로 설명되는가?
- CTA가 하나인가?
- 확인되지 않은 정보나 과장 표현이 없는가?
- 기존 계정의 크림색·주황색·큰 제목·앱 화면 중심 스타일과 어울리는가?
