# Instagram Carousel Prototype

Ramap 기능 화면을 실제 스크린샷 중심의 인스타그램 사용 가이드로 만든다. 먼저 조정 가능한 HTML 시안을 제공하고, 사용자가 확정하면 업로드용 이미지를 만든다.

카드뉴스 파일 제작은 primary agent가 담당한다. 게시물 목표·서사·캡션 기획이 필요하면 `instagram-marketing` 스킬을 적용하고 `.codex/agents/sol/instagram-marketer.md`의 역할에 맞춰 초안을 전달받는다. 이미지 배치만 수정하는 요청에 기획 에이전트를 자동으로 추가하지 않는다.

## Inputs

- 기능 이름과 안내할 핵심 행동
- 앱 화면 스크린샷(순서대로 받기)
- 꼭 들어갈 문구 또는 제거할 문구
- 참고 게시물·색상·스타일(있다면)

날짜, 이벤트명, 매장 정보처럼 사실성이 중요한 내용은 화면이나 사용자가 제공한 정보로만 쓴다. 부족하면 필요한 화면만 요청한다.

## Workflow

1. 기능을 사용 흐름 기준으로 4~6장으로 나눈다. 표지는 피드 그리드에서도 기능이 즉시 읽히도록 `OO 화면 사용 방법`으로 쓴다.
2. 카드마다 `한 가지 메시지 + 해당 앱 화면`만 배치한다. 카드 수, 제목, 문구, 화면 파일을 먼저 짧게 제안한다.
3. 사용자가 화면을 제공하면 HTML 프로토타입을 만든다.
   - 작업 위치는 현재 채팅에 제공된 visualization workspace를 우선한다. 별도 위치가 없으면 사용자 전역 `~/.codex/visualizations/<date>/<id>/` 아래에 저장한다. 저장소의 `.codex` 에이전트·명령 문서와 생성물을 섞지 않는다.
   - 파일명은 `ramap-<feature>-guide-prototype.html`을 사용한다.
   - 카드 캔버스는 4:5 비율(1080×1350 기준)로 한다.
   - 사용자가 다른 규격을 지정하면 그 규격을 모든 카드와 내보내기에 동일하게 적용한다. `instagram-marketing`의 3:4 피드 기본값 때문에 기존 4:5 시안을 자동 변경하지 않는다.
   - 클릭 가능한 카드 탐색과 현재 카드 수를 제공한다.
4. 수정은 요청한 범위만 적용한다. 이미지 교체, 문구 삭제, 카드 합치기는 기존 카드를 불필요하게 다시 만들지 않는다.
5. 사용자가 “업로드 파일 만들어줘” 또는 명확히 확정하면 각 카드를 1080×1350 PNG로 내보내고, 순서가 보이는 파일명과 ZIP을 만든다.

## Copy fidelity and Korean typesetting

- 사용자가 확정한 문구는 원본으로 취급한다. 레이아웃 수정 중 문구를 윤문·요약·재배열하거나 줄바꿈을 추가·제거하지 않는다.
- 문단 구분은 사용자가 제공한 위치만 유지한다. 카드에 맞추기 위한 `<br>` 삽입은 하지 않는다.
- 한글 본문은 단어·음절 중간에서 줄바꿈되지 않도록 `word-break: keep-all`을 적용한다. 공간이 부족하면 먼저 본문 폭과 이미지 위치를 조정하고, 그다음에만 글자 크기를 조정한다.
- 타이포그래피 CSS를 바꾼 뒤에는 영향을 받는 모든 카드를 다시 렌더링해 제목·본문·이미지가 잘리지 않고 원문 단어가 끊기지 않는지 눈으로 확인한다.

## Visual Rules

- 실제 앱 스크린샷을 사용한다. 내부 문구·아이콘·마커는 임의로 재현하거나 변경하지 않는다.
- 화면은 `object-fit: contain`을 기본으로 하며 찌그러뜨리지 않는다. 정보가 잘리는 문제가 있으면 카드 안의 화면 영역·비율·위치를 먼저 조정한다.
- 카드 바깥 영역은 Ramap의 크림·주황 계열 그라데이션, 은은한 점 질감, 큰 한글 제목을 기본 스타일로 사용한다. 사용자가 다른 레퍼런스를 주면 그 스타일을 우선한다.
- 앱의 실제 마커·아이콘·브랜드명은 저장소 자산을 사용한다. 브랜드 표기는 `라멥`으로 쓴다.
- 앱 화면과 설명은 시선 흐름이 맞게 배치한다. 설명선이 필요하면 대상 UI와 같은 높이에 정확히 맞춘다.
- 첫 표지의 캐러셀 점은 기본적으로 넣지 않는다. 사용자가 점 또는 보조 문구를 제거하라고 하면 해당 카드에서 완전히 없앤다.
- 카드에 긴 문구를 넣지 않는다. 한 장에 한 행동만 설명하고, 필요하면 카드를 합치거나 분리한다.

## Review Checklist

- 첫 장만 봐도 어떤 화면의 가이드인지 알 수 있는가?
- 카드 번호·총 장수·탐색 버튼이 실제 카드 수와 일치하는가?
- 모든 제공 이미지 경로가 유효하고 비율이 보존되는가?
- 중요한 매장명·주소·행사 정보가 잘리지 않는가?
- 사용자가 요청한 삭제 항목(문구·점·보조 설명)이 남아 있지 않은가?
- HTML 스크립트 구문을 확인한 뒤 전달하는가?
- 각 PNG를 해당 카드만 활성화한 상태로 내보냈는가? 수정된 카드의 실제 PNG를 확인했는가?

## Delivery

- 시안 단계: HTML 파일을 Codex의 `open_in_codex`로 보여주고 절대 경로의 파일 링크를 안내한다.
- 최종 단계: PNG 폴더와 ZIP 파일의 절대 경로 링크, 카드 수와 실제 적용한 규격을 함께 안내한다. 수정한 대표 카드를 이미지로 보여주고 내보낸 모든 카드의 잘림과 순서를 확인한다.
- 인스타그램 게시·예약·외부 업로드는 사용자의 별도 승인이 있어야 한다.
